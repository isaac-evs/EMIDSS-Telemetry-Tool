# EMIDSS-8 Telemetry & Control UI Architecture

This directory houses the modernized, high-performance desktop user interface and telemetry processing pipeline for the **EMIDSS-8** payload. It replaces the legacy synchronous Python prototype with a robust, decoupled **Tauri** desktop application powered by a **Rust** backend and a **React/TypeScript** web frontend.

---

## 1. Executive Summary & Achievements So Far

The legacy Python codebase (`EMIDSSV_GUI.py`) suffered from severe architectural bottlenecks, including synchronous I/O blocking the main OS UI loop, artificial thread throttling (`time.sleep`), manual spreadsheet copy-pasting for charting, and fatal application crashes when encountering hardware noise.

The new UI architecture solves these issues through several major engineering milestones achieved so far:

* **Strict Decoupling (Tauri Architecture):** The frontend renders natively in the host operating system's webview, completely isolated from the backend hardware communication layer.
* **Asynchronous Non-Blocking I/O (`tokio-serial`):** Serial connection monitoring runs on a dedicated green thread (`tokio`). High-frequency byte streams are buffered and parsed asynchronously without causing UI lag or frame drops.
* **Automated In-Memory Data Pipeline (`polars`):** Bulk memory dumps (`BEGIN_DUMP` to `END_DUMP`) are intercepted out of the standard log stream and routed directly into a high-speed Rust `Polars` DataFrame engine. Missing sensor values are automatically interpolated (`forward_fill`) in memory before serialization.
* **Defensive Hardware Parsing:** Built to survive dirty or corrupted serial streams. Incoming raw bytes are processed via lossy UTF-8 converters (`String::from_utf8_lossy`), and tabular parsing relies strictly on safe `Result/Option` pattern matching. Garbage bytes log warnings rather than triggering unwrap panics.
* **Command Timeout Protection:** Outbound hardware commands (e.g., `ReadMemory`, `ReadTime`) initiate an asynchronous watcher. If the payload fails to acknowledge or respond within **3 seconds**, explicit timeout warnings are emitted to the operator console.
* **Minimal Binary Footprint:** Release optimization profiles (`lto = true`, `codegen-units = 1`, `panic = "abort"`, `strip = true`) guarantee a standalone native executable under 25MB.

## 2. Backend <-> Frontend Communication (IPC Bridge)

Communication between the Rust hardware core and the React web interface is handled securely via Tauri's Inter-Process Communication (IPC) bridge using **Commands** (inbound requests) and **Events** (outbound broadcasts).

### 2.1. Outbound Commands (Frontend -> Backend via `invoke`)

The web frontend invokes Rust functions asynchronously using `@tauri-apps/api/core`:

| Command Name | Payload Parameters | Return Type | Description |
| :--- | :--- | :--- | :--- |
| `get_avaible_ports` | *None* | `Result<String[], String>` | Scans the host system and returns a list of detected active COM/UART port names (e.g., `["COM3", "/dev/ttyUSB0"]`). |
| `connect_uart` | `port: string`<br>`baudrate: number` | `Result<(), String>` | Spawns background `tokio` reader/writer channels connected exclusively to the specified hardware device. |
| `send_command` | `action: string` | `Result<(), String>` | Translates semantic UI actions into serial protocols (`"Memory"` $\rightarrow$ `b"S2202\n"`, `"Time"` $\rightarrow$ `b"S2201\n"`, `"Reset"` $\rightarrow$ `b"S2203\n"`) and starts a 3s response timeout watcher. |

#### Example Frontend Invocation:
```typescript
import { invoke } from "@tauri-apps/api/core";

// Send a memory read command to the EMIDSS payload
await invoke("send_command", { action: "Memory" });
```

---

### 2.2. Inbound Events (Backend -> Frontend via `emit` / `listen`)

The Rust core pushes real-time telemetry and status updates up to the web frontend using event broadcasting:

| Event Name | Payload Data Type | Description |
| :--- | :--- | :--- |
| `uart-rx` | `string` | Emits live standard log lines received from the serial stream for display in the scrolling operator terminal. |
| `uart-error` | `string` | Emits critical warnings such as command response timeouts, corrupted memory dump alerts, or hardware disconnection notices. |
| `telemetry-update` | `TelemetryRow[]` (JSON Array) | Emits fully processed, cleaned, and interpolated environmental data arrays generated by the Polars DataFrame engine. |

#### `telemetry-update` JSON Schema:
When a bulk memory dump completes, the frontend charting dashboard receives a clean JSON array structured as follows:

```json
[
  {
    "Time": "11:13",
    "Temperature": 27.05,
    "Humidity": 53.51,
    "Pressure": 839.10
  },
  {
    "Time": "11:14",
    "Temperature": 27.06,
    "Humidity": 53.46,
    "Pressure": 838.97
  },
  {
    "Time": "11:15",
    "Temperature": 27.06,
    "Humidity": 53.46,
    "Pressure": 839.02
  }
]
```

#### Example Frontend Listener:
```typescript
import { listen } from "@tauri-apps/api/event";

interface TelemetryRow {
  Time: string;
  Temperature: number;
  Humidity: number;
  Pressure: number;
}

// Listen for normalized data from Polars
const unlisten = await listen<TelemetryRow[]>("telemetry-update", (event) => {
  console.log("Received cleaned dataset:", event.payload);
  // Update D3 / Chart.js graphs here
});
```

## 3. Directory Structure & Key Files

To navigate the codebase efficiently, prioritize the following core files which contain the primary logic of the application:

```text
UI/
├── App/
│   ├── src-tauri/
│   │   ├── Cargo.toml            [Backend Dependencies & Release Optimizations]
│   │   └── src/
│   │       └── main.rs           [Core Rust Engine: Async UART, Polars, Defensive Parsing]
│   ├── src/
│   │   ├── App.tsx               [Main Application Layout Shell]
│   │   └── components/
│   │       ├── ConnectionManager.tsx  [COM Port Selector & Connect Logic]
│   │       └── TerminalConsole.tsx    [Live Scrolling Log Viewer]
│   └── package.json
└── Docs/
    ├── audit.md                [Legacy Codebase Engineering Audit]
    ├── sdd.md                  [Software Design Document & ADRs]
    └── srs.md                 [Software Requirements Specification]
```

### Highlights of Critical Files:

1. **`UI/App/src-tauri/src/main.rs`**
   * *The heart of the backend.* It manages stateful UART connections (`AppState`), runs the `tokio` async serial loops, handles defensive lossy string conversions, intercepts `BEGIN_DUMP` / `END_DUMP` blocks, interpolates missing values via `Polars`, and enforces command timeouts.
2. **`UI/App/src-tauri/Cargo.toml`**
   * Configures crates (`tokio`, `tokio-serial`, `polars`, `serde_json`) and defines the explicit `[profile.release]` rules guaranteeing high execution speed and compact binary generation.
3. **`UI/App/src/components/ConnectionManager.tsx`**
   * The primary hardware configuration interface. Manages COM port discovery (`get_avaible_ports`) and establishes the active UART connection (`connect_uart`).
4. **`UI/App/src/components/TerminalConsole.tsx`**
   * The real-time visualizer for standard system logs. Subscribes to the `uart-rx` event stream and auto-scrolls incoming telemetry data cleanly.
5. **`UI/Docs/*`**
   * Contains the foundational specifications (`srs.md`), design trade-offs (`sdd.md`), and historical review (`audit.md`) that guided the modernization of the EMIDSS-8 UI.
